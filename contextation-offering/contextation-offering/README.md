# Offering · Contextation

Minimal launch scaffold for **https://offering.contextation.com**. A separate site from viiibrant.org, adapted from the tested password-gate pattern in the owner's `viiibrant-hair` repository. **Nothing in this repository deploys to viiibrant.org.**

## What's included

- Cloudflare Worker (`src/worker.js`) checks the shared password before serving **any** page or asset.
- `SITE_PASSWORD` is a **Cloudflare encrypted runtime secret**. The actual value is not present in the repository.
- A signed, host-bound, `Secure` + `HttpOnly` + `SameSite=Strict` session cookie lasts up to seven days. Changing `SITE_PASSWORD` invalidates old sessions.
- Protected static starter (`dist/index.html` and `dist/styles.css`), with **no map, storage, accounts, or class data yet**.
- Local authentication tests (`npm run check`) and a custom-domain route for `offering.contextation.com`.

## Launch using GitHub + Cloudflare

1. In GitHub, create a **new private repository** named `contextation-offering`. Keep `viiibrant-hair` unchanged. Upload the **contents** of this folder to the repository root (not the ZIP itself). Commit to `main`.
2. In Cloudflare, use the account where `contextation.com` is Active. Go to **Workers & Pages → Create application → Import a repository** (wording may vary), connect GitHub, and choose `contextation-offering`. Create a new Worker, **not** a deployment of the existing `viiibrant-hair` Worker. If selecting a Worker name manually, enter `contextation-offering`.
3. Use the following build settings:

   | Setting | Value |
   | --- | --- |
   | Production branch | `main` |
   | Root directory | `/` (repository root) |
   | Build command | `npm run check` |
   | Deploy command | `npx wrangler deploy` |

   Keep Cloudflare's autogenerated GitHub/build credentials; do not paste tokens into source. If Cloudflare offers non-production preview builds, disable them for this private site. `preview_urls: false` in `wrangler.json` also disables Worker version previews.
4. The first build may publish a harmless **"Almost ready"** setup page. Open **Workers & Pages → contextation-offering → Settings → Variables and Secrets** and create a **Secret** named exactly `SITE_PASSWORD`, with a unique strong passphrase **12–256 characters** long. **Deploy** after setting it. Do not create this value as a plaintext `var`, commit it to Git, or reuse the viiibrant.org password.
5. Check **Settings → Domains & Routes** for `offering.contextation.com`. It is declared in `wrangler.json`; Cloudflare should attach the custom domain and provision HTTPS automatically when the Worker is deployed in the correct account. **Do not manually replace working DNS records unless Cloudflare displays an explicit conflict.** If it reports a DNS, zone, or permission conflict, inspect it before changing DNS.
6. Test the Worker `workers.dev` URL and the custom URL in a fresh private/incognito window:
   - `/` **and** `/styles.css` redirect to `/_gate/login` when unauthenticated.
   - Incorrect password remains blocked; correct password opens the landing page.
   - Direct asset URLs cannot be accessed anonymously.
   - Sign out using `/_gate/logout` and verify re-entry requires the password.
   - HTTPS is active and the site shows no content before the password is configured.
7. To update the landing page later, edit `dist/` and push to GitHub `main`. Cloudflare Builds will run the tests and deploy from the repository.

## Develop or test locally

Node.js 20+ recommended:

```sh
npm ci
npm run check
# Local optional preview (the password must be provided locally, never committed):
npx wrangler dev --local-protocol https
```

The local test suite uses a deliberately fake password and requires **no Cloudflare credentials**. If running a local preview, supply `SITE_PASSWORD` via an untracked `.dev.vars` file, which is ignored by Git.

## Guardrails for later development

- **Do not remove** `assets.run_worker_first: true`, change the Worker route, or enable unauthenticated preview deployments.
- Preserve separate secrets and session cookies for the offering and hair brief.
- Avoid cache-everything rules that could cache authenticated content for other visitors.
- This is **shared-password access**, not individually verified accounts. It has no built-in brute-force login rate limiting; use a long unique passphrase and add Cloudflare rate limiting before wider distribution.
- The starter has no database or participant information. Before adding hometown pins or memories, define consent, retention, deletion, moderation, and whether participant entries are anonymous to each other.

## The offering itself (added Nov 2026)

- `/` is **the wall**, behind the password: the zoom-out, the threads, the pins. Keys: `→` next thread, `h` hometown, `p` play, `e` type places in, `x` clear the room, `r` restart.
- `/join` is **open** (no password): what classmates open on their phones. Find a place by name or tap the map, add a name if they like, hold it; at the end of class, where they came from.
- `/api/pin` (open, POST) receives a pin; `/api/pins` and `/api/clear` need the wall's session; `/api/geocode` is a place search (Photon, biased toward campus with `local=1`).
- The room is one **Durable Object** (`Room` in `src/worker.js`, bound as `ROOM`). The deploy creates it through the `migrations` entry in `wrangler.json` — no dashboard step. `x` on the wall empties it.
- Map pages get a wider Content-Security-Policy (map library from cdnjs, tiles from OpenFreeMap, Google Fonts); every other response keeps the strict one.
- The first landing page is kept at `/first-landing` (behind the password).
